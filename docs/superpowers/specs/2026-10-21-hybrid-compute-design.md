# 云端业务与桌面模型计算设计

日期：2026-10-21
关联：[todo-021](../../tasks/todo-021.md)
性质：依据购买前资源试验形成的设计，尚非生产实现或上线结论。

## 目标与已选分工

个人学习演示，以中国大陆访客为主，只需在演示时段提供模型问答。网页、账号、业务API、PostgreSQL/pgvector、原始文档、BGE向量计算、权限与引用校验实际运行在云端。本机只执行预先配置的Ollama模型生成任务。

服务器候选为上海2核2GiB/40GiB轻量，学生券结算预览0元/半年，域名候选cdzlab.cn。购买依赖完整验证，不提前消耗学生券。用户已同意先验证该分工；本设计将新增的计算任务边界写清。

## 选择依据与舍弃方案

2026-10-21基线实测：32片×395 token虚构TXT真实解析/索引、API真实BGE查询、注册登录、权限、历史和统计均通过；生成使用Mock。第一轮五个业务容器同时工作集采样峰值889.81MiB。

第二轮把五个容器内存上限合计约束为1376MiB、CPU配额合计2核，再次通过同一链路。为2GiB标称总内存留下672MiB预算，但这只是容器试验，不能冒充独立2GiB整机、真实桌面生成往返或公网性能验收。详见[资源报告](../../operations/hybrid-preflight-report.md)。

因此先选改动最少的“云端BGE、本机生成”。暂不增加桌面embedding队列、Redis/RocketMQ或GPU云服务器。若后续真实链路/解析大文件/并发试验显示余量不足，再重新评估迁移BGE或提高配置，不先实现两套计算方案。

## 数据流

1. 浏览器通过云端同源HTTPS登录、上传、提问和查看历史。
2. 云端保留现有身份校验、知识库范围、查询向量、SQL检索、提示词构造和调用限额。
3. 新的QueuedProvider将一次generate请求写入业务数据库的计算任务表。桌面主动通过固定HTTPS地址领取。
4. 桌面只调用本机预先配置的Ollama模型，完整回传受限输出和usage。不能领取任意URL、文件路径、命令或模型下载地址。
5. 云端校验任务和结果，再由现有RAG复核引用及当前权限/来源版本，最后沿用现有SSE和聊天持久化。

现有RAG在引用校验前不会展示上游文本，第一版无需跨机逐token协议。桌面不直连数据库，不公开本机端口，不承载公网网页，不转发访客HTTP/TCP。

## 数据契约

首版仅有generate任务。新增ComputeWorker和ComputeJob最少两张表，业务结果仍归现有Message。

ComputeJob至少包含job_id、kind、state、worker_id、attempt、lease_token摘要、lease_until、deadline、关联generation_token、payload、result、result_digest和时间字段。状态为queued/running/succeeded/failed/cancelled。关联消息或generation token来自服务端，不由桌面提供。聊天生成入口将reservation/message/generation token放入严格按异步任务隔离的ContextVar作用域，QueuedProvider在其中创建关联任务，finally恢复上下文；不改现有Provider.stream签名。测试两个并发会话的上下文不会串线。

任务payload包含现有LLMMessage列表、允许的模型标识、max_tokens和temperature。沿用RAG输入12000 UTF-8字节、最多512输出tokens、完成文本8192字符等既有上限；原始JSON输入最多64KiB、结果最多64KiB。HTTP入口在完整读取前限制body，不只依靠结构验证。

结果只允许约定的text、finish_reason、模型标识、usage或脱敏失败类别。finish_reason必须区分stop、length等，截断不能冒充成功；usage只接受供应商实际非负数值，缺失保持未知。结果不能提供检索候选、知识库范围、引用、SQL或业务写入指令。

## 认证和入口

节点使用独立高熵机器凭据，数据库只存摘要且可撤销；不复用管理员Cookie、数据库密码。凭据保存在受控配置，不进入命令参数、日志、浏览器或Git。

新增独立机器接口：
- POST /internal/compute/claim
- POST /internal/compute/{job_id}/heartbeat
- POST /internal/compute/{job_id}/result

这些接口采用Bearer认证和no-store。机器凭据只允许上述操作；管理员Cookie没有Bearer时也不能领取。现有/api/v1写请求的Cookie、Origin和CSRF保护不变。

当前Caddy仅转发/api和/health，需要为精确/internal/compute前缀增加转发；未匹配机器API不得落入SPA页面。逐路由验证认证、撤销凭据、body上限、错误JSON和no-store。公网只开放网站HTTP/HTTPS；数据库和Ollama保持内部。

## 调度、租约与取消

桌面一次执行一个生成任务。云端最多16个排队任务，沿用最多2个活动聊天请求，不因离线无限积压。

节点每1秒轮询、每5秒续租；租约15秒。任务的绝对deadline由调用方剩余RAG预算决定，所有排队、领取、网络和生成共用现有60秒总预算，心跳不能延长。生成最多领取一次，无透明重试、无云模型回退。冷模型在演示前预热。

原子领取绑定节点、attempt和新租约令牌。提交时同时核对运行状态、节点、租约、绝对期限和generation token。租约过期则任务失败，旧节点不能恢复提交。重复相同结果依据有界摘要幂等确认，冲突结果拒绝。

浏览器停止/断网、转人工、删除会话或禁用用户，均须撤销对应计算任务；晚结果不能复活旧回复。心跳独立于Ollama调用运行，发现取消或租约无效即关闭本地流并取消调用。需实测Ollama是否停止计算；若关闭流后计算尚未停止，节点不得继续领取并叠加调用，须报告受控失败，不能把Python等待取消当作GPU已释放。

本次不改变同步BGE行为和现有入库租约。BGE线程取消并不会中断编码，仍需在结果使用前复核权限/版本；不新增桌面embedding重试与入库续租耦合。

## 重启、消费和清理

API重启保留现有generating消息恢复为PROCESS_RESTARTED的行为，并撤销关联未完成计算任务；桌面重启不重新执行此前丢失的生成任务。

云端消费结果采用原子状态转换和取回；只有持有消费权的一方可交给原聊天generation写入。消费完成后立即清空任务payload/result；失败/取消后立即清空。保留结果摘要供重复提交确认，摘要不包含原文。

应用启动和每分钟执行清理，24小时过期元数据在下次清理移除，因此最长保留约24小时加一个清理周期。元数据最多10000行，写入前清理到边界；容量无法释放则拒绝新增。清理与消费使用同一状态/行锁协议，不能抢先删除尚未被有效消费者取回的结果。

成功但尚未消费的结果也受原generation有效性和deadline约束：generation已失效、deadline已过或API重启恢复判定没有有效消费者时，在同一事务核对消费权后清空payload/result，即使任务状态已经succeeded；不得因等待不存在的消费者永久留存。覆盖“结果已接受但HTTP确认丢失”“结果已接受、消费者取回前崩溃”“消费后进程崩溃”“清理与提交/消费并发”；沿用重启恢复失败语义，不补写成功或重复问答。

4. 重测受限资源下的完整目标链路；补PDF/DOCX、索引与查询并发、登录峰值、磁盘/日志、重启及OOM行为。当前128MiB解析容器仅证明小TXT，不作为所有20MiB文档的默认生产限额。
5. 在独立2GiB系统或可审计系统预算下确认OS/Docker余量；本机试验不保证阿里云共享CPU、网络或磁盘表现。运行统一check与专项检查并独立评审。
