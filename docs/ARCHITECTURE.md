# 架构与范围基线

日期：2026-09-22。来源：用户确认的总体方向及“先写详细计划，不开始业务开发”的请求。本文是本轮实现计划的设计依据；后续任务内可细化，跨模块契约更改必须同步文档。

## 1. 目标与验收闭环

管理员维护 FAQ 和文档；有权限的用户自然语言提问、看到基于知识的回答与来源；无资料时澄清或申请转人工；客服接单、回复并结束会话；用户提交反馈；管理员查看处理记录和统计。上述功能能够通过公开 HTTPS 地址使用，数据库与文件在服务重启后保留。

本地增强目标：本机运行小模型接入同一 RAG；完成一次可复现的轻量微调和独立评测。若用户选定“自有模型线上运行”，增加推理服务发布任务。基础网站发布不必等待训练结束，增强工作仍保留在待办中。

## 2. 初始假设与范围

- 单套系统、多知识库、小规模初期使用；角色 `user`、`agent`、`admin`。首个演示场景由用户提供，未提供时仅使用标注为虚构的校园服务样例。
- 企业、校园、政务是内容适配场景，共用系统；本期不建立 SaaS 租户、独立计费或跨机构组织树。
- 文本型 PDF、DOCX、UTF-8 TXT/Markdown；扫描件识别为不可提取并给出提示，OCR 单独新增任务时再实施。
- 客服为站内文字客服；使用会话状态、接单队列和短轮询完成基础实时效果。模型回答通过 SSE 流式返回。语音、电话及外部客服平台另行登记。
- 数据保存在服务器持久卷与 PostgreSQL。正式环境和开发环境的数据、模型密钥互相隔离。
- 本轮没有承诺容量、速度或回答准确率；用固定数据集和验收报告记录实际结果。

## 3. 技术选型

| 层 | 基线 |

| 前端 | Node.js 24 LTS、Vue 3、TypeScript、Vite、Element Plus、ECharts、npm lockfile |

| 数据库 | PostgreSQL 16、pgvector；确切镜像版本在 todo-001 验证后固定，不使用漂移的 latest |
| 文档 | pypdf、python-docx；普通文本用标准库读取 |

| 部署 | Linux、Docker Compose、Caddy；web/api/worker/db，训练不放进常驻业务容器 |

精确补丁版本在 todo-001 和模型任务开始时核对兼容性并写入锁文件。训练依赖与后端 uv 环境分离，避免 GPU 工具链牵连普通 CPU 部署。

## 5. 数据和权限

核心实体：User、AuthSession、KnowledgeBase、KnowledgeMembership、FAQ、Document、DocumentRevision、Chunk、IngestionJob、Conversation、Message、Handoff、Feedback、AuditEvent。

知识库分 `public`（所有已登录用户可读）与 `restricted`（成员可读），匿名用户不读取业务数据。管理员管理所有内容；客服可以查询本人有权使用的知识，并只读取本人已接单的会话内容；排队列表仅显示必要摘要。用户只查看自己的历史和反馈。基础版本仅管理员管理知识库成员与发布内容。

所有文档读取、检索、引用展开和下载均以当前身份过滤。前端隐藏按钮不是权限控制。禁用/删除的文档立即从可检索集合排除；历史回答保留生成时快照，来源现已失效或无权限时不再返回片段/下载。历史回答已经披露的文本不自动撤回，产品应明确这个边界。

## 6. 文档入库与恢复

上传先做权限、扩展名/实际解析能力、大小检查；初始上限每文件 20 MiB。原文件使用服务端随机标识存储，用户文件名只作显示，不参与路径拼接。PDF/DOCX 解析设置时间与资源边界；无可提取文本报告失败。

DocumentRevision 保存原文件哈希与版本，Chunk 保存标题/页码/顺序、文本、模型版本、向量。分段按模型 token 上限处理，不能把无限长文本直接送入 embedding。FAQ 也产生可检索片段，不维护第二套答案索引。

后台任务存在数据库中，单独 worker 领取执行。状态持久化、每步幂等、失败可重试；使用租约/心跳恢复中途退出的任务。避免只靠 Web 进程内临时任务承载上传流程。解析与索引是两类任务，解析后文档处于parsed待索引状态；todo-006交付解析，todo-007完成真实向量索引。候选新版本可建索引但不可检索，索引成功后原子切换有效版本；替换期间旧版本仍可检索，旧新版本不会混用。

## 7. RAG 与会话

使用最近有限轮已持久化消息辅助补全追问；检索范围由服务端确定，用户文本或模型生成不能扩大权限。检索结果先进行足够性判断，无证据时返回澄清/无答案状态；不以模型自报概率作为置信度。

证据片段编号后送入提示词，引用只允许来自本轮候选集合；文档中的指令属于数据，不能覆盖系统约束。模型可生成未经证据支持的内容，因此评测需人工核对，不宣称零幻觉。

每个会话同一时刻只生成一个助手回复。用户消息先持久化，助手消息保存 `generating/complete/failed/cancelled` 状态；断连、超时和重试可看到实际状态，不能出现两条重复答案。人工接管使用数据库状态转换阻止机器人继续向已接管会话写回复。

## 8. 上线边界

优先方案：普通云服务器运行业务、数据库和 CPU embedding，生成通过云 API；Caddy 提供同域网页/API/HTTPS，数据库端口不向公网开放。公共预发布必须有测试账号和鉴权，不放入私有材料。

自有模型：本机用于实验，线上另接持续运行的推理服务。训练只在需要时执行；训练权重和数据不进 Git。模型服务必须经后端访问，不把未鉴权的模型端口公开。

上线前完成登录和上传限制、模型调用限流与用量上限、依赖版本锁定、数据备份及恢复演练。部署以已验证的 commit/tag 和镜像为单位，记录版本；GitHub 合并与生产发布是两件事，合并不会自动获得购买或发布权限。

## 9. 测试重点

权限泄漏、资料已删除/禁用、上传中断、无答案问题、流中断与人工接管竞争，是跨模块必须覆盖的五类场景。对应任务分别为 todo-002/005/007、todo-006/008、todo-006、todo-008/013、todo-009/010。

算法测试使用固定开发/验证/测试划分；近重复问答与同源材料避免跨训练/测试泄漏。分别评估检索、引用/回答、拒答、延迟，不能仅用模型自评或单个示例宣称微调有效。
