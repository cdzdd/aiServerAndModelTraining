# 2026-10-01 本地 QLoRA 训练记录

本次在 RTX 5070 Ti 16GB 上完成原始 Qwen3-4B-Instruct-2507 的真实 QLoRA 训练与计划停止后恢复。数据为 8 条原创虚构格式教学样本、2 条独立校报验证样本；独立代理逐题审核，不属于人工业务审核。最终 20 steps 的极低验证 loss 只反映这两条格式样本的学习，不证明真实业务泛化或问答性能提升。

| 阶段 | 真实步骤 | 含加载/训练/验证/保存耗时 | CUDA allocated 峰值 | CUDA reserved 峰值 |
| --- | --- | --- | --- | --- |
| smoke | 0→2 | 79.644 秒 | 4,022,468,096 B | 4,418,699,264 B |
| 指定 checkpoint 恢复 | 2→4 | 58.048 秒 | 4,022,468,096 B | 4,418,699,264 B |
| 独立正式训练 | 0→20 | 92.168 秒 | 4,022,468,096 B | 4,420,796,416 B |

CUDA 峰值来自同一训练进程的 `torch.cuda.max_memory_allocated/reserved`，涵盖加载和训练，不是整卡总占用；约 3.75 GiB allocated / 4.12 GiB reserved。正式 Trainer train_runtime=42.4199 秒，train_loss=0.33764393950561955，最终 eval_loss=9.016810508910567e-06，所有 loss 有限。loss 四舍五入显示的 0.0 与原始精度区分记录。所有观察日志、JSON 和 trainer_state 保留在本 worktree 忽略目录 `.local/finetuning/`。

smoke 正常结束后，resume_from_checkpoint 显式加载 checkpoint-2 的 adapter、optimizer、scheduler 与 RNG，trainer_state 到 step 4；本次没有制造强制崩溃或声称恢复掉电。正式 train 使用独立目录从原始基座重新训练，与 smoke 制品分开。save_steps=2 保存全部 10 份正式 checkpoint；权重和状态身份见 [制品清单](training-artifacts-2026-10-01.json)。

首次 smoke 启动在模型加载前失败：WSL Linux git 无法识别 Windows worktree 的 .git pointer。原始失败日志 `smoke-launch-failed-windows-git.log` 保留；观察 wrapper 改用 Windows 采集的真实 code SHA 作为参数，不修改 Git 元数据和训练超参，然后实际 2-step 成功。

基座为 `Qwen/Qwen3-4B-Instruct-2507`，Apache-2.0，固定修订 `cdbee75f17c01a7cc42f958dc650907174af0554`。训练采用 NF4 4-bit double quantization、BF16、SDPA、LoRA rank 8/alpha 16/all、cutoff 1024、micro-batch 1、梯度累积 4、constant LR 5e-5、seed 42；没有根据评测结果调参。真实 qwen3_nothink 模板的完整输入与目标长度 366–403 tokens，10 条均未截断。数据 manifest SHA256 为 `024255b602eb9a7b69089431ff5966a68540f07403c06c0ae75a2cf1e4cb66ec`。

Adapter 含 16,515,072 个参数、504 个张量；全部 13 个 adapter 目录（smoke 的 2 个 checkpoint、正式训练的 10 个 checkpoint 与最终根目录）逐张量核验为有限值。最终 `adapter_model.safetensors` 为 66,126,768 字节，SHA256 `83381c072f0df17e4541f91478d3f4aba278652eb843df8dc1fdaaf5e6825e26`；`adapter_config.json` SHA256 `b1f2f2ab02fb97611f51f21227a0653862db908153e53443c3cbf061ca345e1d`。未合并完整权重或转换 GGUF。

精确来源、许可、文件/配置/adapter 哈希、数据计数、恢复状态与资源原始字段由制品清单提供。训练实现代码 SHA 为 `2fade598fd9c7e7c51250aceb8d2e5832bee6847`；正式评测使用独立桥接实现所在 `49d3ded90f34969122a841258f7dedd4af0c6cbf`。GPU 先由 016 真实本地验收释放、Ollama 已加载模型正常卸载后供训练独占使用。

复现方式见 [实验教程](../README.md)。基座和 adapter 同 NF4/BF16/Factory 运行栈的结果见 [对照报告](comparison-2026-10-01.md)，模型是否适合真实应用须按实际评测和资料边界决定。

首轮推理对照后来被独立评审发现实际采用采样：Factory虽在 achat 层请求 do_sample=False，Transformers 4.57.6 会把等于全局默认的 False 覆盖为模型默认 True。桥接服务在加载后对齐实际 model.generation_config.do_sample=False，并通过真实 Transformers 回归与独立 PEFT tiny-Qwen3 CPU generate 验证 GREEDY_SEARCH；随后保持训练数据、adapter 与全部超参不变，重新运行四组对照。原首轮结果保留为 [v1-sampled 历史](v1-sampled/README.md)，正式结论见新对照报告。模型缓存中的 generation_config.json 保持原始哈希，修正只发生在加载后的内存对象。

另一次微调 API 启动因训练 venv 路径误拼而在模型加载前返回 127；`api-finetuned-launch-path-failed.log` 保留，修正路径后启动成功，没有重新训练。Windows 汇总 comparison JSON 的默认编码曾导致中文不可按 UTF-8 解析，后从四份完整原始 JSON 用显式 UTF-8 重建；原始逐题报告未损坏。

当前微调 API 和基座网页的真实就绪状态及整卡空闲测量见 [部署快照](local-deployment-2026-10-01.json) 与实验教程。该测量与上述训练进程 CUDA 峰值属于不同范围，不能相加或当作并发训练保证。
